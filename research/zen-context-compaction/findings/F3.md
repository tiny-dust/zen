# F3: 商业 IDE/桌面端 AI 编程工具的上下文管理与自动摘要策略

Research date: 2026-10-12. All sources are official documentation/changelog pages fetched directly (search engines DDG/Bing were unusable; see Dead ends). Windsurf docs reflect the post-Cognition-acquisition "Devin Desktop" rebrand (Cascade retained as legacy agent name).

## Findings

### [1] VS Code (GitHub Copilot) auto-compacts the conversation when the context window fills, and this is user-disableable via a named setting `github.copilot.chat.summarizeAgentConversationHistory.enabled`
- quote: "VS Code automatically compacts the conversation when the context window fills. To turn off automatic compaction, set `github.copilot.chat.summarizeAgentConversationHistory.enabled` to `false`."
- url: https://code.visualstudio.com/docs/agents/run/sessions/manage-sessions
- source_type: primary
- published: unknown (docs accessed 2026-10-12)
- confidence: high

### [2] VS Code manual compaction via `/compact` accepts free-text retention instructions that steer what the summary keeps
- quote: "Type `/compact` in the chat input. Optionally, add instructions for what the summary should retain, for example `/compact focus on the database schema decisions`." — plus: "Manual compaction is available for local, background, and Claude agent sessions."
- url: https://code.visualstudio.com/docs/agents/run/sessions/manage-sessions
- source_type: primary
- published: unknown (docs accessed 2026-10-12)
- confidence: high

### [3] VS Code surfaces live context-window telemetry in the chat input: usage ratio, token count, per-category breakdown, and AI-credit spend
- quote: "The context window control in the chat input shows how much of the model's context window the active chat is using. Hover over the control to see the token count, a usage breakdown by category, and the total AI credits consumed by the session."
- url: https://code.visualstudio.com/docs/agents/run/sessions/manage-sessions
- source_type: primary
- published: unknown (docs accessed 2026-10-12)
- confidence: high

### [4] VS Code prescribes what to keep vs drop: durable instructions live in custom instructions (re-injected every request), and an unrelated task means a new session — never rely on history for cross-session facts
- quote: "Start a new session when you switch to an unrelated task. If an instruction should apply across requests or sessions, store it in custom instructions instead of relying on conversation history."
- url: https://code.visualstudio.com/docs/agents/concepts/context
- source_type: primary
- published: unknown (docs accessed 2026-10-12)
- confidence: high

### [5] VS Code treats fork-vs-new-chat as a cost decision: forking inherits full history explicitly to preserve the provider prompt cache, while a new chat starts blank
- quote: "A forked session inherits the conversation history of the original, which preserves the prompt cache and reduces cost on the next request."
- url: https://code.visualstudio.com/docs/agents/run/sessions/manage-sessions
- source_type: primary
- published: unknown (docs accessed 2026-10-12)
- confidence: high

### [6] Windsurf Cascade @-mentions of past conversations inject conversation summaries and checkpoints — deliberately not the full transcript — to avoid overflowing the context window
- quote: "Cascade will retrieve the most relevant and useful information like the conversation summaries and checkpoints, and specific parts of the conversation that you query for. It typically will not retrieve the full conversation as to not overwhelm the context window."
- url: https://docs.windsurf.com/windsurf/cascade/cascade
- source_type: primary
- published: unknown (docs accessed 2026-10-12)
- confidence: high

### [7] Windsurf Memories: Cascade auto-generates durable facts during conversations, stores them locally per-workspace in `~/.codeium/windsurf/memories/`, and retrieves them when it judges them relevant — at no credit cost
- quote: "During conversation, Cascade can automatically generate and store memories if it encounters context that it believes is useful to remember." — plus: "Cascade retrieves them when it believes they're relevant." and "Creating and using auto-generated memories do NOT consume credits."
- url: https://docs.windsurf.com/windsurf/cascade/memories
- source_type: primary
- published: unknown (docs accessed 2026-10-12)
- confidence: high

### [8] Windsurf rule activation modes are designed around explicit context-window cost: always_on (every message) vs model_decision (only the description enters the system prompt; full rule read on demand) vs glob vs manual — with hard size caps of 6,000 chars global / 12,000 chars per workspace rule file
- quote: "This controls when the rule's content is given to Cascade and how much context window it consumes" — "Model Decision | `model_decision` | Only the `description` is shown in the system prompt. Cascade reads the full rule file when it decides the description is relevant."
- url: https://docs.windsurf.com/windsurf/cascade/memories
- source_type: primary
- published: unknown (docs accessed 2026-10-12)
- confidence: high

### [9] Windsurf Cascade runs a background planning agent that continuously maintains a long-term plan (Todo list) so the main model's context stays focused on short-term actions
- quote: "In the background, a specialized planning agent continuously refines the long-term plan while your selected model focuses on taking short-term actions based on that plan."
- url: https://docs.windsurf.com/windsurf/cascade/cascade
- source_type: primary
- published: unknown (docs accessed 2026-10-12)
- confidence: high

### [10] Cursor's documented long-conversation strategy is user-directed forking and new chats, not automatic summarization: Restore Checkpoint reverts files only, and shortening history requires forking from an earlier message
- quote: "Restoring reverts files only; it does not remove messages from the conversation. To shorten the conversation itself, fork the chat from an earlier message."
- url: https://cursor.com/help/ai-features/agent
- source_type: primary
- published: unknown (docs accessed 2026-10-12)
- confidence: medium (absence-of-feature claim — current public docs describe no auto-compact; behavior may exist undocumented)

### [11] Cursor side chats (`/side`, `/btw`) isolate exploration from the main thread by using the parent conversation as hidden reference context while keeping their own transcript
- quote: "A side chat is a durable agent conversation. It uses the parent thread as hidden reference context and keeps its own transcript."
- url: https://cursor.com/docs/agent/overview
- source_type: primary
- published: unknown (docs accessed 2026-10-12)
- confidence: high

### [12] Cursor Projects (launched 2026-09-10) attacks long-horizon context loss with persistent shared-context files synced across every agent (cloud and local), where agents append research/artifacts and learned codebase knowledge over months
- quote: "Each Project maintains a set of files that sync across every cloud and local machine its agents use. Agents add research and artifacts, along with what they learn about the codebase and how you prefer work to be done." — and: "The shared context grows with the Project, making the coordinator more effective over time."
- url: https://cursor.com/changelog/projects
- source_type: primary
- published: 2026-09-10
- confidence: high
