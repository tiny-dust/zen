# F1: Claude Code 与 Anthropic 生态的上下文压缩机制

## Findings

### [1] Claude Code 的 auto-compact 默认按"绝对 token 窗口"触发：默认压到模型上下文上限，原生 1M 窗口模型约在 967K tokens 触发，未开 extended context 的 Sonnet 4.6/Opus 4.6 在 200K 边界触发
- quote: "Models running with a native 1M window compact before the window fills, at about 967K tokens by default."
- url: https://code.claude.com/docs/en/model-config
- source_type: primary
- published: unknown (current docs, 2026)
- confidence: high

### [2] auto-compact 窗口可在 100K–1M tokens 之间配置，有四个入口（`/autocompact` 命令、`autoCompactWindow` 设置项、`--autocompact` 启动旗标、`CLAUDE_CODE_AUTO_COMPACT_WINDOW` 环境变量），会被封顶在模型上下文窗口内，且按模型分别保存；子代理可用 frontmatter 单独设更早的窗口
- quote: "The command and the flag accept a window size from 100K to 1M tokens" … "Added `autoCompactWindow` to subagent frontmatter and `--agents` definitions, so a subagent can auto-compact earlier than the main conversation's window"
- url: https://code.claude.com/docs/en/model-config ; https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md (v2.1.288 / v2.1.296)
- source_type: primary
- published: 2026 (v2.1.288–v2.1.296)
- confidence: high

### [3] auto-compact 的演进：v0.2.47 首次引入"自动压缩对话以支持无限长度（/config 可开关）"，v0.2.98 修复过重复触发，v1.0.51 把上下文告警阈值从 60% 提到 80%
- quote: "Increased auto-compact warning threshold from 60% to 80%"
- url: https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md (v0.2.47 / v0.2.98 / v1.0.51)
- source_type: primary
- published: 2025 (版本号未带日期)
- confidence: high

### [4] 压缩的执行流程：Claude Code 发起一个独立的摘要请求（与主对话相同的 system prompt、tools 和完整历史，末尾追加一条总结指令作为最后一条 user 消息）；缓存温热时该请求只付增量成本，但压缩必然使对话层缓存失效、并从磁盘重载项目上下文；不需要连续性时 `/clear` 是零成本替代
- quote: "To produce the summary, Claude Code sends a separate request with the same system prompt, tools, and history as your conversation, plus a summarization instruction appended as a final user message."
- url: https://code.claude.com/docs/en/prompt-caching ; https://code.claude.com/docs/en/costs
- source_type: primary
- published: unknown (current docs, 2026)
- confidence: high

### [5] 官方明确"压缩后保留什么"：结构化摘要保留用户请求与意图、关键技术概念、涉及/修改的文件及重要代码片段、报错与修复方式、待办与当前工作，丢弃原样工具输出与中间推理；随后自动重读最近修改的最多 5 个文件（>5K tokens 的文件只留路径引用）、按每个 skill ≤5K/总计 ≤25K tokens 重注入已调用 skill 正文（最旧的先丢）、重跑 `compact` 来源的 SessionStart hook；自 v2.1.198 摘要请求继承会话的 extended thinking 配置
- quote: "Claude Code re-reads up to five of the files Claude has read or edited in the session, choosing the ones modified most recently."
- url: https://code.claude.com/docs/en/context-window
- source_type: primary
- published: unknown (current docs, 2026)
- confidence: high

### [6] Anthropic 工程博客给出压缩设计原则：摘要要保住架构决策、未解决 bug 和实现细节、丢弃冗余工具输出与消息，agent 携带压缩上下文 + 最近访问的 5 个文件继续；实现建议先最大化召回再迭代精度（避免过度压缩丢失后续才发现关键的隐性上下文）
- quote: "The model preserves architectural decisions, unresolved bugs, and implementation details while discarding redundant tool outputs or messages. The agent can then continue with this compressed context plus the five most recently accessed files."
- url: https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents
- source_type: primary
- published: 2025-09-29
- confidence: high

### [7] 压缩可被定向引导：`/compact` 可带焦点指令（如 `/compact focus on the auth bug fix`），CLAUDE.md 可写 "# Compact instructions" 段落定制保留偏好；PreCompact hook 可用 exit code 2 或 `{"decision":"block"}` 阻止压缩（v2.1.105）
- quote: "`/compact Focus on code samples and API usage` tells Claude what to preserve during summarization."
- url: https://code.claude.com/docs/en/costs ; https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md (v1.0.48 / v2.1.105)
- source_type: primary
- published: 2025–2026
- confidence: high

### [8] 存在"反应式/恢复压缩"路径：当压缩后的请求仍超长，Claude Code 会再次压缩并保留更少的近期对话（v2.1.141 起首次摘要尝试按原始请求的溢出尺寸做种子，避免浪费一次近全量重试）；已知边界情况包括无完整早期交换可摘要时永久卡死、系统睡眠导致放弃并报 "Prompt is too long"、网关改写错误文本导致恢复失败
- quote: "when the compacted request is still too long, Claude Code now compacts once more, keeping less of the recent conversation"
- url: https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md
- source_type: primary
- published: 2025–2026 (版本号未带日期)
- confidence: high

### [9] Claude Code 客户端侧做了"工具结果清理"（社区称 microcompact，官方 changelog/文档无此词）：v2.1.50 "处理后清除大工具结果以改善长会话内存占用"，官方把 "tool-result clearing" 与 compaction 并列为预期内缓存重建原因
- quote: "1 expected rebuild (compaction or tool-result clearing)"
- url: https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md (v2.1.50) ; https://code.claude.com/docs/en/costs
- source_type: primary
- published: 2026
- confidence: high (行为) / medium (命名归属)

### [10] Anthropic API 的 context editing（beta 头 `context-management-2025-06-27`）提供 `clear_tool_uses_20250919` 策略：按 `trigger`（input_tokens 阈值）激活，按时间序清除最旧工具结果、可配 `keep`（保留最近 N 次 tool_uses）、`clear_at_least`（最少清除 token 数，因清除会使 prompt cache 失效而设）、`exclude_tools`、可选 `clear_tool_inputs`；清除后以占位文本替代；另有 `clear_thinking_20251015` 清早期 thinking 块；编辑发生在服务端，客户端保留完整历史无需同步
- quote: "The API replaces each cleared result with placeholder text indicating to Claude that it was removed."
- url: https://platform.claude.com/docs/en/build-with-claude/context-editing
- source_type: primary
- published: 2025 (beta); docs current 2026
- confidence: high

### [11] context editing 与 memory tool 于 2025-09-29 随 Claude Sonnet 4.5 发布（public beta，含 Bedrock/Vertex）：内部 agentic search 评测中 memory tool + context editing 较基线提升 39%（仅 context editing 提升 29%）；100 轮 web search 评测中 context editing 让原本因上下文耗尽而失败的流程跑完、token 消耗降 84%；Sonnet 4.5 内置"上下文感知"全程跟踪剩余 token
- quote: "combining the memory tool with context editing improved performance by 39% over baseline. Context editing alone delivered a 29% improvement."
- url: https://www.anthropic.com/news/context-management
- source_type: primary
- published: 2025-09-29
- confidence: high

### [12] memory tool（`memory_20250818`，纯客户端文件操作 view/create/str_replace/insert/delete/rename，限 `/memories` 目录）与压缩互补：API 自动注入系统指令要求开工前先看 memory 目录并"假设中断"随时记录进度；官方建议长跑 agent 两者并用——压缩负责无客户端记账地缩小活跃上下文，memory 保住必须跨摘要存活的信息
- quote: "compaction keeps the active context small without client-side bookkeeping, and memory preserves the information that must survive summarization."
- url: https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool
- source_type: primary
- published: 2025; docs current 2026
- confidence: high

### [13] 子代理隔离是官方推荐的上下文节省手段：子代理拥有独立上下文窗口（自己的 system prompt、加载 CLAUDE.md、不含主对话历史与主会话 auto memory），工作全程不计入主上下文，只有最终文本回复 + 少量元数据回到主会话；官方示例中子代理读了 6,100 tokens 文件、只返回 420 tokens；工程博客给出量级估计"每个子代理可能消耗数万 tokens，只返回约 1,000–2,000 token 摘要"；成本文档明确建议把测试/文档/日志类高吞吐操作委托给子代理
- quote: "The subagent read 6,100 tokens of files. You got a 420-token result. That's the context savings."
- url: https://code.claude.com/docs/en/context-window ; https://code.claude.com/docs/en/costs ; https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents
- source_type: primary
- published: 2025-09-29 / 2026 docs
- confidence: high

## Suggested follow-ups
- Anthropic 新增的 server-side compaction API（platform.claude.com/docs/en/build-with-claude/compaction，被 context-editing 文档标注为"长对话首选策略"）值得单独精读，对 Zen 的 API 层设计可能有直接参考价值。
- Claude Agent SDK 的压缩编程接口（autoCompact 回调/开关、compaction 事件流）——Zen 若要复刻 auto-compact，SDK 层的回调设计是现成范式。
- Claude Code 如何在第三方/自定义网关上识别 "prompt is too long" 错误形状并触发恢复压缩（CLAUDE_CODE_DISABLE_UNKNOWN_MODEL_WINDOW_ENFORCEMENT 的行为）——Zen 调 OpenAI 兼容 API 时错误识别是同类问题。
