# F4: 开源 CLI/agent 工具的上下文压缩实现（Cline/Roo Code/Aider/OpenHands/Goose）

## Findings

### [1] Cline 将上下文管理做成三条 slash 命令：/newtask（蒸馏开新任务）、/smol 与别名 /compact（就地压缩对话为摘要，继续同一任务）
- quote: "`/smol` (or its alias `/compact`) compresses your conversation history while preserving essential context. Unlike `/newtask` which creates a new task, `/smol` condenses your current conversation into a comprehensive summary, freeing up context window space while allowing you to continue working in the same task."
- url: https://docs.cline.bot/core-workflows/using-commands.md
- source_type: primary
- published: unknown (docs current as of 2026-10)
- confidence: high

### [2] Roo Code "Intelligent Context Condensing" 默认开启，由上下文窗口占用百分比滑杆触发（默认值 100%），支持自定义压缩提示词（存于 customSupportPrompts.CONDENSE）和手动 "Condense Context" 按钮
- quote: "**Threshold to trigger intelligent context condensing**: A percentage slider (default 100%) that determines when condensing activates based on context window usage (found in "Context" settings) ... Your custom condense prompt is stored using the same support-prompt override mechanism as other prompt templates: `customSupportPrompts.CONDENSE`."
- url: https://roocodeinc.github.io/Roo-Code/features/intelligent-context-condensing
- source_type: primary
- published: 2026-05-15 (docs page last updated)
- confidence: high

### [3] Roo Code 默认预留 30% 上下文窗口（20% 模型输出 + 10% 安全缓冲），仅 70% 可用于对话历史；token 计数优先用厂商原生端点（如 Anthropic count-tokens），失败时回退 tiktoken 估算，图片按 300 tokens/张保守估算
- quote: "By default, 30% of the context window is reserved (20% for model output and 10% as a safety buffer), leaving 70% available for conversation history. ... Falls back to tiktoken estimation if API calls fail ... Image content: Uses a conservative estimate of 300 tokens per image"
- url: https://roocodeinc.github.io/Roo-Code/features/intelligent-context-condensing
- source_type: primary
- published: 2026-05-15 (docs page last updated)
- confidence: high

### [4] Roo Code 有独立的"溢出自动恢复"层：检测到 provider 返回上下文窗口超限错误后，自动将上下文削减 25% 并重试（不需人工干预），与阈值压缩形成两层防线
- quote: "**Error Detection**: Roo Code detects context window errors from multiple providers (OpenAI, Anthropic, and others) **Automatic Truncation**: The system automatically reduces the context by 25% **Retry Mechanism**: After truncation, Roo Code retries your request (up to the built-in retry limit)"
- url: https://roocodeinc.github.io/Roo-Code/features/intelligent-context-condensing
- source_type: primary
- published: 2026-05-15 (docs page last updated)
- confidence: high

### [5] Roo Code 压缩强制使用当前会话的同一 provider/model（不允许换更便宜的模型做摘要），理由是混合模型会破坏 tool call/结构化内容的翻译一致性
- quote: "Condensing always uses your active conversation provider/model. Using a different model to condense can degrade summary quality when the history includes tool calls, tool results, or other structured content. Keeping condensing on the same model/provider avoids \"translation\" errors between different tool/format expectations."
- url: https://roocodeinc.github.io/Roo-Code/features/intelligent-context-condensing
- source_type: primary
- published: 2026-05-15 (docs page last updated)
- confidence: high

### [6] Aider 的自动摘要器 ChatSummary（aider/history.py）：默认预算 max_tokens=1024；超限时保留近期尾部消息（约一半预算），头部按"模型 max_input_tokens−512"分块送弱模型摘要；摘要以单条 user 消息回注并补一条 assistant "Ok."，递归深度上限 3、min_split=4
- quote: "model_max_input_tokens = self.models[0].info.get(\"max_input_tokens\") or 4096; model_max_input_tokens -= 512  # reserve buffer for safety ... summary = prompts.summary_prefix + summary; return [dict(role=\"user\", content=summary)] ... if messages and messages[-1][\"role\"] != \"assistant\": messages.append(dict(role=\"assistant\", content=\"Ok.\"))"
- url: https://raw.githubusercontent.com/Aider-AI/aider/main/aider/history.py
- source_type: primary
- published: unknown
- confidence: high

### [7] Aider 与各家不同：不主动执行 token 预算管理，只在 API 返回超限错误后报告并给出 /tokens、/drop、/clear 等建议；仓库地图是它控制上下文的固定预算组件（默认 1024 tokens）
- quote: "Aider never *enforces* token limits, it only *reports* token limit errors from the API provider. ... Use `/tokens` to see token usage. Use `/drop` to remove unneeded files from the chat session. Use `/clear` to clear the chat history."
- url: https://aider.chat/docs/troubleshooting/token-limits.html
- source_type: primary
- published: unknown
- confidence: high

### [8] OpenHands SDK 默认 condenser 为 LLMSummarizingCondenser：事件数超过 max_size 触发，恒定保留前 keep_first 条事件（system prompt + 初始用户消息），被丢弃事件替换为一条 LLM 生成的摘要；官方宣称每轮 API 成本最多降 2x 且任务表现持平或更好
- quote: "This condenser triggers when there are more than `max_context_length` events in the conversation history, and always keeps the first `keep_first` events (system prompts, initial user messages) to preserve important context. ... Up to **2x reduction** in per-turn API costs ... `LLMSummarizingCondenser` extends the `RollingCondenser` base class"
- url: https://docs.openhands.dev/sdk/guides/context-condenser
- source_type: primary
- published: unknown (Software Agent SDK era, 2025–2026)
- confidence: high

### [9] OpenHands Agent Server 把"强制压缩"做成一等 REST 端点（condense-conversation），压缩是可从外部按需触发/审计的操作而不只是内部自动行为
- quote: "Condense Conversation — Force condensation of the conversation history."
- url: https://docs.openhands.dev/llms.txt (API reference page: sdk/guides/agent-server/api-reference/conversations/condense-conversation)
- source_type: primary
- published: unknown
- confidence: medium (index quote verified; full endpoint page not individually fetched)

### [10] Goose 的自动压缩阈值取 min(配置阈值, 225,000/上下文窗口)：默认压缩阈值 0.8，另设 DEFAULT_AUTO_COMPACT_TOKEN_LIMIT=225_000，刻意在 OpenAI 长上下文高价档（>272k input tokens）之下留出余量；阈值 ≤0 或 ≥1 表示禁用
- quote: "pub const DEFAULT_AUTO_COMPACT_TOKEN_LIMIT: usize = 225_000; /// Starts compaction with headroom below OpenAI's long-context price tier (above 272k input tokens). This is not a maximum request size. ... threshold.min(token_limit as f64 / context_limit as f64) ... usage_ratio > threshold"
- url: https://raw.githubusercontent.com/aaif-goose/goose/main/crates/goose/src/context_mgmt/mod.rs
- source_type: primary
- published: unknown
- confidence: high (0.8 默认值由该文件单元测试注释 "// Default threshold (0.8)" 佐证)

### [11] Goose 压缩的落地方式是"可见性元数据翻转"而非删除：全部原始消息转为 agent_invisible（用户界面仍可见），把结构化摘要（经 compaction.md/compaction_summary.md 模板渲染，含 user_intent/files/pending_tasks/current_work 字段）与一条 assistant 续接指令以 agent-only 身份插入，同时原样保留最近一条纯文本用户消息；provider.manages_own_context()（如 ACP 托管上下文的 agent）时完全跳过压缩
- quote: "Your context was compacted. The previous message contains a summary of the conversation so far. Do not mention that you read a summary or that conversation summarization occurred. Just continue the conversation naturally based on the summarized context."
- url: https://raw.githubusercontent.com/aaif-goose/goose/main/crates/goose/src/context_mgmt/mod.rs
- source_type: primary
- published: unknown
- confidence: high

### [12] Goose 的工具结果治理是可选项（GOOSE_TOOL_PAIR_SUMMARIZATION，默认关）：按批次（TOOLCALL_SUMMARIZATION_BATCH_SIZE=10）把最老的 tool request/response 配对发给 LLM 一句话摘要，触发条件为"可摘要工具对数 > cutoff+批次"，cutoff = clamp(3×有效限额/20000, 10, 500)，且永不触碰当前轮次最后 N 个工具调用；主压缩摘要请求遭 ContextLengthExceeded 时还有渐进式移除工具响应的兜底
- quote: "pub(crate) const TOOLCALL_SUMMARIZATION_BATCH_SIZE: usize = 10; ... (3 * effective_limit / 20_000).clamp(10, 500) ... Never summarize the last N tool calls (current turn) ... test_progressive_removal_on_context_exceeded"
- url: https://raw.githubusercontent.com/aaif-goose/goose/main/crates/goose/src/context_mgmt/mod.rs
- source_type: primary
- published: unknown
- confidence: high
