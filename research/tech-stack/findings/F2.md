# F2: Editor and terminal UI

## Findings

### [1] Monaco Editor 0.56.0 (current latest, July 2026) is generated from VS Code sources and has no version mapping to VS Code itself
- quote: "The Monaco Editor is generated straight from VS Code's sources with some shims around services the code needs to make it run in a web browser outside of its home." / "None. The Monaco Editor is a library and it reflects directly the source code."
- url: https://github.com/microsoft/monaco-editor
- source_type: primary
- published: 2026 (repo current; package.json version 0.56.0)
- confidence: high

### [2] Monaco 0.55.0 added first-class native LSP support (`lsp` namespace); 0.56.0 added tree-shakeable ESM entry points plus `advanced-external`/`advanced-wasm` diff algorithms and typed native LSP client/transport APIs
- quote: "Adds native LSP support (see new `lsp` namespace)." / "Reorganizes the exported ESM modules to provide supported, tree-shakeable entry points" / "Adds `advanced-external` and `advanced-wasm` diff algorithms. Exposes typed native LSP client and transport APIs."
- url: https://github.com/microsoft/monaco-editor/blob/main/CHANGELOG.md
- source_type: primary
- published: 2026 (0.56.0 and 0.55.0 entries; 0.56.0 references editor core `0.56.0-dev-20260625`)
- confidence: high

### [3] Monaco 0.53.0 deprecated the AMD build; ESM + a bundler (Vite/webpack) is now the required integration path, and VS Code extensions do not run in Monaco
- quote: "⚠️ This release deprecates the AMD build and ships with significant changes of the AMD build." / "I've written an extension for VS Code, will it work on the Monaco Editor in a browser? No." / "the ESM build should be used with a bundler, such as vite or webpack."
- url: https://github.com/microsoft/monaco-editor/blob/main/CHANGELOG.md
- source_type: primary
- published: 2026 (0.53.0 entry)
- confidence: high

### [4] Full monaco-editor npm package is extremely large (~93 MB unpacked, 1909 files); CodeMirror 6 core packages are orders of magnitude smaller (@codemirror/state ~440 KB, @codemirror/view ~1.25 MB, meta package `codemirror` ~21 KB)
- quote: monaco-editor@0.56.0 "unpackedSize":97911464, "fileCount":1909; @codemirror/state@6.7.4 "unpackedSize":439987; @codemirror/view@6.43.11 "unpackedSize":1253700; codemirror@6.0.2 "unpackedSize":21258
- url: https://registry.npmjs.org/monaco-editor/latest
- source_type: primary
- published: 2026 (registry latest tags as of research date)
- confidence: high

### [5] CodeMirror 6 is intentionally modular (state/view/commands/language as separate packages); the `codemirror` meta package only pulls baseline editor features, and languages are opt-in per package
- quote: "The core packages, without which it'd be hard to set up an editor at all, are: `@codemirror/state` … `@codemirror/view` … `@codemirror/commands`" / "the `codemirror` package pulls in most of the things you need for a baseline editor (except a language package)."
- url: https://codemirror.net/docs/guide/
- source_type: primary
- published: unknown (docs current as of 2026)
- confidence: high

### [6] Official CodeMirror 6 merge/diff UI is `@codemirror/merge` (split `MergeView` + `unifiedMergeView`); the GitHub mirror was archived Apr 15 2026 after canonical hosting moved to code.haverbeke.berlin
- quote: "This package implements a merge interface for the CodeMirror code editor." / "A split merge view can be created like this: import {MergeView} from \"@codemirror/merge\"" / "This repository was archived by the owner on Apr 15, 2026. It is now read-only." / "This repository has moved to https://code.haverbeke.berlin/codemirror/merge"
- url: https://github.com/codemirror/merge
- source_type: primary
- published: 2026-04-15 (archive date)
- confidence: high

### [7] Vue 3 + CodeMirror 6 has a maintained thin wrapper (`vue-codemirror` 6.1.1, Vue3-only, 3.5k GitHub stars); Monaco has no first-party Vue wrapper and community options split between an outdated egoist/vue-monaco (Vue2/webpack/AMD era) and `@guolao/vue-monaco-editor` 1.6.0 (Vue2&3 via vue-demi + @monaco-editor/loader)
- quote: "CodeMirror(6) component for Vue(3)." / "v5/v6 has been released. This is a new version based on CodeMirror@6 and is available to Vue3 only." / @guolao/vue-monaco-editor: "Monaco Editor for Vue 2&3 - use the monaco-editor in any Vue application without needing to use webpack (or rollup/vite) configuration files / plugins", peerDependencies monaco-editor ">=0.43.0"
- url: https://github.com/surmon-china/vue-codemirror
- source_type: primary
- published: vue-codemirror@6.1.1 (npm); @guolao/vue-monaco-editor@1.6.0 (npm, published 2025-01)
- confidence: high

### [8] LSP path for Monaco is mature: TypeFox `monaco-languageclient` 11.x-next is aligned to monaco-editor 0.56.0 / VS Code 1.129.1 and ships JSON/Python/Java/Groovy/clangd-wasm examples; CodeMirror has no official LSP client and relies on Lezer parsers plus community LSP adapters
- quote: "Aligned with: @codingame/monaco-vscode-[editor]-api 36.2.7 / vscode 1.129.1 / monaco-editor 0.56.0" / "monaco-languageclient to connect Monaco editor with language servers." / CodeMirror languages exist as "full parser package[s], often with language-specific integration" via Lezer (e.g. lang-javascript, lang-python, lang-rust)
- url: https://github.com/TypeFox/monaco-languageclient
- source_type: primary
- published: 2026 (versions table current)
- confidence: high

### [9] Monaco ships multi-language support as first-party Monarch/tokenizer + worker-backed CSS/HTML/JSON/TS language features (tree-shakeable since 0.56.0 via `monaco-editor/languages/definitions/*` and `languages/features/*`); CodeMirror ships ~20 official Lezer lang packages plus legacy-modes and community packages
- quote: Monaco 0.56.0: "all language definitions with `monaco-editor/languages/definitions/register.all`, or individual definitions with `monaco-editor/languages/definitions/<language>/register`; the CSS, HTML, JSON, and TypeScript language features with `monaco-editor/languages/features/register.all`" / CodeMirror: list includes Angular, CSS, C++, Go, HTML, Java, JavaScript, JSON, Markdown, PHP, Python, Rust, SQL, Vue, XML, YAML + "collection of CodeMirror 5 modes" and "community-maintained language packages"
- url: https://github.com/microsoft/monaco-editor/blob/main/CHANGELOG.md
- source_type: primary
- published: 2026
- confidence: high

### [10] Terminal stack is the VS Code production pair: xterm.js 6.0.0 (`@xterm/xterm`, zero core deps, optional GPU renderer) + node-pty 1.1.0 (Microsoft-maintained, conpty on Windows 1809+, winpty removed); xterm.js is explicitly not a shell and expects a pty driver like node-pty
- quote: "Xterm.js is a frontend component that enables applications to bring fully-featured terminals to their users in the browser. It's used by popular projects such as VS Code (and its forks), Tabby and Hyper." / "Xterm.js is not `bash`. Xterm.js can be connected to processes like `bash` and let you interact with them … through a library like node-pty." / node-pty: "forkpty(3) bindings for node.js" / "Support for the `winpty` library has been removed. Windows 10 version 1809 (build 18309) or later is now required." / "Node.JS 16 or Electron 19 is required"
- url: https://github.com/xtermjs/xterm.js/blob/master/README.md
- source_type: primary
- published: @xterm/xterm@6.0.0 and node-pty@1.1.0 (npm latest as of 2026-09-12)
- confidence: high

### [11] Official xterm.js addons include Fit (`@xterm/addon-fit`) and WebGL2 renderer (`@xterm/addon-webgl` 0.19.0, ~2.4 MB unpacked); WebGL requires explicit `onContextLoss` handling because browsers can drop the WebGL context
- quote: Fit: "An addon for xterm.js that enables fitting the terminal's dimensions to a containing element." / WebGL: "An addon for xterm.js that enables a WebGL2-based renderer." / "The browser may drop WebGL contexts for various reasons like OOM or after the system has been suspended. There is an API exposed that fires the `webglcontextlost` event … an easy way … is by disposing of WebglAddon when the event fires: addon.onContextLoss(e => { addon.dispose(); })"
- url: https://github.com/xtermjs/xterm.js/tree/master/addons/addon-webgl
- source_type: primary
- published: 2026 (addon-webgl@0.19.0)
- confidence: high

### [12] Concurrent terminal sessions are implemented as one `Terminal` instance + one node-pty process per session; node-pty is not thread-safe across Node worker threads, and `@xterm/headless` exists for Node-side state without a DOM view
- quote: node-pty README "Note that node-pty is not thread safe so running it across multiple worker threads in node.js could cause issues." / xterm.js README: "We also publish `@xterm/headless` which is a stripped down version of xterm.js that runs headless in Node.js. An example use case for this is to keep track of a terminal's state where the process is running and using the serialize addon so it can get all state restored upon reconnection." / Wiring: "pty.onData(data => term.write(data)); term.onData(data => pty.write(data));"
- url: https://github.com/microsoft/node-pty
- source_type: primary
- published: 2026
- confidence: high

### [13] Monaco DiffEditor is a first-class product surface (used by VS Code): new widget became default in 0.42.0, old implementation removed in 0.44.0, and 0.56.0 added advanced-external/advanced-wasm algorithms — stronger out-of-the-box side-by-side/inline diff than CodeMirror's MergeView for agent apply/patch review
- quote: "Uses new diff editor widget by default. Use `experimental.useVersion2: false` to use the old widget. The old widget will be replaced in the next update." (0.42.0) / "Removes old diff editor implementation." (0.44.0) / "Diff editor uses inline mode by default when width is too small. Use the config option `useInlineViewWhenSpaceIsLimited`"
- url: https://github.com/microsoft/monaco-editor/blob/main/CHANGELOG.md
- source_type: primary
- published: 2024–2026 (changelog entries)
- confidence: high

## Dead ends
- WebSearch tool unavailable in this environment; research done via direct WebFetch of primary sources only.
- npmjs.com package HTML pages return HTTP 403; used registry.npmjs.org JSON API instead.
- `codemirror.net/examples/merge/` 404; merge API confirmed via GitHub codemirror/merge README.
- Bundlephobia / size.dev style comparative gzipped numbers not retrieved (blocked); used npm unpackedSize as a relative magnitude proxy — not identical to shipped minified/gzipped payload.
- No first-party Vue wrapper exists for either editor; quality comparison of wrappers is based on repo READMEs + npm metadata, not runtime benchmarks.
