# F5: Skills, storage, packaging, competitors

## Findings

### [1] Agent Skills is an open standard: a skill is a folder with required SKILL.md (YAML frontmatter + Markdown body); `name` is required, 1–64 chars, lowercase alphanumerics and hyphens only, must match parent directory name; `description` is required, 1–1024 chars.
- quote: "A skill is a directory containing, at minimum, a `SKILL.md` file... `name` | Yes | Max 64 characters. Lowercase letters, numbers, and hyphens only. Must not start or end with a hyphen... Must match the parent directory name"
- url: https://agentskills.io/specification
- source_type: primary
- published: unknown (live docs as of 2026-09)
- confidence: high

### [2] Agent Skills uses progressive disclosure in three stages: metadata (~100 tokens) at startup, full SKILL.md body (<5000 tokens recommended) on activation, bundled scripts/references/assets only when required; keep SKILL.md under 500 lines.
- quote: "Metadata (~100 tokens): The `name` and `description` fields are loaded at startup for all skills... Instructions (< 5000 tokens recommended): The full `SKILL.md` body is loaded when the skill is activated... Resources (as needed)... Keep your main `SKILL.md` under 500 lines."
- url: https://agentskills.io/specification
- source_type: primary
- published: unknown (live docs as of 2026-09)
- confidence: high

### [3] Agent Skills is adopted industry-wide: Claude Code, Cursor, GitHub Copilot, VS Code, Gemini CLI, OpenCode, Roo Code, Amp, Goose, ChatGPT/Codex, Cline, and many more all document SKILL.md compatibility.
- quote: "The Agent Skills format was originally developed by Anthropic, released as an open standard, and has been adopted by a growing number of agent products."
- url: https://agentskills.io
- source_type: primary
- published: unknown (live docs as of 2026-09)
- confidence: high

### [4] Claude Code skill discovery is layered: enterprise managed-settings, personal `~/.claude/skills/<name>/SKILL.md`, project `.claude/skills/`, nested monorepo paths (lazy-load on first file touch under that subdir), plugins (`/plugin:skill`), and `--add-dir` extras; conflict precedence is enterprise > personal > project.
- quote: "Where you save a skill decides which sessions load it... Enterprise `.claude/skills/<skill-name>/SKILL.md` in the managed settings directory... Personal `~/.claude/skills/<skill-name>/SKILL.md`... Project `.claude/skills/<skill-name>/SKILL.md`... Enterprise over personal, and personal over project."
- url: https://docs.anthropic.com/en/docs/claude-code/skills
- source_type: primary
- published: unknown (live docs as of 2026-09; cites Claude Code v2.1.x behaviors)
- confidence: high

### [5] Claude Code extends Agent Skills frontmatter well beyond the open standard: `disable-model-invocation`, `user-invocable`, `allowed-tools`/`disallowed-tools`, `context: fork` + `agent` + `background`, `model`, `effort`, `hooks`, `paths` (glob activation), `when_to_use`, `argument-hint`, `arguments`, `shell`; description+when_to_use truncated at 1,536 chars in skill listings.
- quote: "the combined `description` and `when_to_use` text is truncated at 1,536 characters in the skill listing to reduce context usage."
- url: https://docs.anthropic.com/en/docs/claude-code/skills
- source_type: primary
- published: unknown (live docs as of 2026-09)
- confidence: high

### [6] Claude Code splits persistence into user-written CLAUDE.md (always loaded at session start; target under 200 lines, hard skip over 4 MiB) vs Claude-written auto memory under `~/.claude/projects/<project>/memory/` (MEMORY.md index: first 200 lines or 25KB loaded; topic files on demand); path-scoped rules use `.claude/rules/*.md` with `paths:` frontmatter.
- quote: "The first 200 lines of `MEMORY.md`, or the first 25KB, whichever comes first, are loaded at the start of every conversation... Claude Code loads a CLAUDE.md file of up to 4 MiB in full and skips a larger file."
- url: https://docs.anthropic.com/en/docs/claude-code/memory
- source_type: primary
- published: unknown (live docs as of 2026-09)
- confidence: high

### [7] Claude Code stores sessions as JSONL transcripts at `~/.claude/projects/<project>/<session-id>.jsonl` where `<project>` is the working-dir path with non-alphanumerics replaced by `-` (truncated to 200 chars + hash); default retention is 30 days via `cleanupPeriodDays`; each line is a message/tool-use/metadata JSON object, but the format is internal and may break scripts across versions.
- quote: "By default, Claude Code stores transcripts as JSONL at `~/.claude/projects/<project>/<session-id>.jsonl`... Each line is a JSON object for a message, tool use, or metadata entry. The entry format is internal to Claude Code and changes between versions, so scripts that parse these files directly can break on any release."
- url: https://docs.anthropic.com/en/docs/claude-code/sessions
- source_type: primary
- published: unknown (live docs as of 2026-09)
- confidence: high

### [8] Cursor implements the same SKILL.md standard and discovers skills from `.agents/skills/`, `.cursor/skills/`, `~/.agents/skills/`, `~/.cursor/skills/`, plus compatibility paths `.claude/skills/`, `.codex/skills/`, `~/.claude/skills/`, `~/.codex/skills/`; nested skill dirs under monorepos are auto-scoped to that subtree without needing `paths:`.
- quote: "For compatibility, Cursor also loads skills from Claude and Codex directories: `.claude/skills/`, `.codex/skills/`, `~/.claude/skills/`, and `~/.codex/skills/`."
- url: https://cursor.com/docs/context/skills
- source_type: primary
- published: unknown (live docs as of 2026-09; references Cursor 2.4 `/migrate-to-skills`)
- confidence: high

### [9] Cline's open-source monorepo packages a shared agent core as `@cline/sdk`, with surfaces as CLI (`apps/cli`), VS Code extension (repo root, migrating), Desktop App under `apps/examples/desktop-app/` using a Tauri shell + Bun sidecar + Next.js UI (not Electron), plus JetBrains; plan/act modes, `.clinerules`, multi-agent teams whose state persists across sessions, and cron-scheduled agents.
- quote: "Desktop App | Native macOS and Windows app (Tauri shell, Bun sidecar, Next.js UI). | `apps/examples/desktop-app/`"
- url: https://github.com/cline/cline
- source_type: primary
- published: unknown (live GitHub README as of 2026-09-12; 67.9k stars, Apache-2.0)
- confidence: high

### [10] better-sqlite3 is a synchronous native SQLite binding for Node; its README benchmarks it as the baseline vs node-sqlite3/sqlite (11.7× slower for `get()` 1 row, 24.4× for 100-row `iterate()`, 15.6× for 100-row insert-in-transaction) and recommends `journal_mode = WAL`; prebuilt binaries ship for major platforms/architectures, which matters for Electron packaging/rebuild.
- quote: "The fastest and simplest library for SQLite3 in Node.js... `db.pragma('journal_mode = WAL')`... Prebuilt binaries are available for major platforms/architectures."
- url: https://github.com/WiseLibs/better-sqlite3
- source_type: primary
- published: unknown (live GitHub README as of 2026-09-12; 7.5k stars, MIT)
- confidence: high

### [11] macOS Electron apps must be code-signed with a Developer ID Application cert AND notarized (required for distribution outside MAS on 10.15+); several critical APIs break without a stable signature: `safeStorage`/Keychain, `app.setLoginItemSettings`, cookieEncryption fuse, and `autoUpdater` (Squirrel.Mac requires signing for updates to work at all).
- quote: "Squirrel.Mac requires the app to be signed for automatic updates to work at all."
- url: https://www.electronjs.org/docs/latest/tutorial/code-signing
- source_type: primary
- published: unknown (live Electron docs as of 2026-09)
- confidence: high

### [12] Windows code signing: since June 2023 Microsoft requires EV certificates for immediate SmartScreen trust (OV is treated like unsigned for reputation purposes); Azure Artifact Signing is described as the cheapest modern cloud option and works from Linux/macOS via `jsign`; electron-builder reads `CSC_LINK`/`CSC_KEY_PASSWORD`/`WIN_CSC_LINK`/`WIN_CSC_KEY_PASSWORD` and offers `forceCodeSigning: true` to fail CI on missing credentials.
- quote: "since June 2023, Microsoft requires software to be signed with an \"extended validation\" certificate... Azure Artifact Signing... is the cheapest option for code signing on Windows, and it gets rid of SmartScreen warnings."
- url: https://www.electronjs.org/docs/latest/tutorial/code-signing
- source_type: primary
- published: unknown (live Electron docs as of 2026-09)
- confidence: high

### [13] electron-builder + electron-updater is the packaging/update path for Zen-like apps: auto-updatable targets are macOS DMG (+ zip required for Squirrel.Mac), Windows NSIS (Squirrel.Windows is NOT supported by electron-updater), Linux AppImage/DEB/Pacman/RPM; metadata is `latest.yml` / `latest-mac.yml` / `latest-linux.yml`; providers include GitHub Releases, S3, DigitalOcean Spaces, Cloudflare R2, Keygen, and generic HTTP.
- quote: "Squirrel.Windows is not supported. Simplified auto-update is supported on Windows if you use the default NSIS target... `zip` target for macOS is required for Squirrel.Mac, otherwise `latest-mac.yml` cannot be created"
- url: https://www.electron.build/docs/features/auto-update
- source_type: primary
- published: unknown (live electron-builder docs, v27 line, as of 2026-09)
- confidence: high

### [14] electron-builder supports staged rollouts via `stagingPercentage` in channel yml, and release channels latest/beta/alpha driven by semver prerelease suffixes in package.json version plus `generateUpdatesFilesForAllChannels: true` and client-side `autoUpdater.channel = "beta"`; beta users also receive latest, alpha users receive all three.
- quote: "There are three channels, ordered by stability: 1. \"latest\"... 2. \"beta\"... 3. \"alpha\"... `autoUpdater.channel = \"beta\"`... `beta`: users will get \"beta\" and \"latest\" version"
- url: https://www.electron.build/docs/tutorials/release-using-channels
- source_type: primary
- published: unknown (live electron-builder docs as of 2026-09)
- confidence: high

### [15] electron-builder v27 (docs current as of 2026-09) hardens updates: `disableWebInstaller` now defaults true (web installers' payload may skip signature verification; v28 makes disabled-web-installer an error), `allowUnverifiedLinuxPackages` added, and `autoInstallEvent` can be `"onNextLaunch"` so NSIS/AppImage installs at next launch instead of on quit (avoiding OS session-end killing the installer); `onNextLaunch` is planned as the v28 default.
- quote: "As of v27, `AppUpdater.disableWebInstaller` defaults to `true`... `autoUpdater.autoInstallEvent = \"onNextLaunch\"`... `\"onNextLaunch\"` is planned to become the default in v28"
- url: https://www.electron.build/docs/features/auto-update
- source_type: primary
- published: unknown (live electron-builder v27 docs as of 2026-09)
- confidence: high
