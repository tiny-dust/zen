# F1: Electron + Vue 3 desktop stack

## Findings

### [1] Current Electron stable is 44.3.0 (released 2026-09-09), shipping Chromium 152.0.7977.78 and Node.js 24.20.0; support policy is the latest 3 stable majors (44.x / 43.x / 42.x).
- quote: "44.3.0 ... Sep 9, 2026 ... 152.0.7977.78 ... 24.20.0"
- url: https://releases.electronjs.org/
- source_type: primary
- published: 2026-09-09
- confidence: high

### [2] Electron security checklist requires contextIsolation (default since 12.0.0) and process sandboxing (default since 20.0.0); disabling contextIsolation also disables sandboxing regardless of other flags.
- quote: "Context Isolation is the default behavior in Electron since 12.0.0." / "process sandboxing ... default behavior in Electron since 20.0.0." / "Disabling context isolation ... also disables process sandboxing"
- url: https://www.electronjs.org/docs/latest/tutorial/security
- source_type: primary
- published: unknown (docs at v44.3.0)
- confidence: high

### [3] Official IPC pattern: renderer-to-main request/response uses ipcRenderer.invoke + ipcMain.handle; preload must expose one method per channel via contextBridge, never the raw ipcRenderer.on/send APIs, and callbacks must not receive the IpcRendererEvent.
- quote: "We don't directly expose the whole `ipcRenderer.invoke` API for security reasons. Make sure to limit the renderer's access to Electron APIs as much as possible."
- url: https://www.electronjs.org/docs/latest/tutorial/ipc
- source_type: primary
- published: unknown (docs at v44.3.0)
- confidence: high

### [4] Official IPC typing pattern is a TypeScript .d.ts that globally augments Window with an IElectronAPI interface matching the contextBridge surface.
- quote: "You can create a `interface.d.ts` declaration file and globally augment the `Window` interface"
- url: https://www.electronjs.org/docs/latest/tutorial/context-isolation
- source_type: primary
- published: unknown (docs at v44.3.0)
- confidence: high

### [5] electron-vite v5.0.0 is the current release; it builds main/preload/renderer as one toolchain, requires Node.js 20.19+ / 22.12+ and Vite 5.0+, supports renderer HMR plus main/preload hot reload, isolated build, and V8 bytecode source protection; scaffold is `npm create @quick-start/electron@latest -- --template vue-ts`.
- quote: "electron-vite ... v5.0.0 ... Requires Node.js version 20.19+, 22.12+ and Vite version 5.0+"
- url: https://electron-vite.org/guide/
- source_type: primary
- published: unknown
- confidence: high

### [6] electron-vite default dependency handling: main/preload `dependencies` stay external (packaged by electron-builder); renderer `dependencies` are bundled; sandboxed preload must fully bundle (externalizeDeps: false); native .node addons must stay external via build.rollupOptions.external even in full-bundle mode.
- quote: "In preload scripts, disabling dependency externalization is required to support Electron's sandboxed environment." / "these modules must remain external, which can be configured using `build.rollupOptions.external`."
- url: https://electron-vite.org/guide/dependency-handling
- source_type: primary
- published: unknown
- confidence: high

### [7] electron-vite official distribution path pairs with electron-builder (sample yml sets npmRebuild: false and asarUnpack for resources/**/*.node); Electron Forge is also supported but conflicts on outDir (Forge forces `out`, so electron-vite must use `--outDir=dist`).
- quote: "Electron Forge's default output directory is `out` and forbids to override, which conflicts with electron-vite. So we can set `outDir` to `dist`."
- url: https://electron-vite.org/guide/distribution
- source_type: primary
- published: unknown
- confidence: high

### [8] Native modules must be rebuilt for Electron's ABI (BoringSSL vs OpenSSL) with @electron/rebuild; rebuild again after every Electron upgrade; on Windows Electron 4+, win_delay_load_hook must be true or modules fail with "Module did not self-register".
- quote: "the native modules you use will need to be recompiled for Electron" / "After you upgrade Electron, you usually need to rebuild the modules." / "on Electron 4.x and higher, `'win_delay_load_hook': 'true'` is required"
- url: https://www.electronjs.org/docs/latest/tutorial/using-native-node-modules
- source_type: primary
- published: unknown (docs at v44.3.0)
- confidence: high

### [9] node-pty (Microsoft) requires Node.js 16+ or Electron 19+, dropped winpty in favor of ConPTY (Windows 10 1809+), is not thread-safe across worker_threads, and is the proven PTY used by VS Code / Hyper / electerm — including Vue 3 + Electron editors such as Logos and Enjoy Git.
- quote: "Node.JS 16 or Electron 19 is required to use `node-pty`." / "Support for the `winpty` library has been removed. Windows 10 version 1809 (build 18309) or later is now required." / "node-pty is not thread safe"
- url: https://github.com/microsoft/node-pty
- source_type: primary
- published: unknown (fetched 2026-09-12)
- confidence: high

### [10] better-sqlite3 currently bundles SQLite 3.53.4 (WAL, FTS5, JSON1, RTREE, SQLITE_THREADSAFE=2) and supports custom amalgamation via --build-from-source --sqlite3=; for Electron it is a native addon that must remain external and be rebuilt via @electron/rebuild / electron-builder nativeModules.
- quote: "By default, this distribution currently uses SQLite version 3.53.4" / "SQLITE_THREADSAFE=2"
- url: https://raw.githubusercontent.com/WiseLibs/better-sqlite3/master/docs/compilation.md
- source_type: primary
- published: unknown
- confidence: high

### [11] electron-builder v27 is the current next docs line: requires Node.js >=22.12.0, is native ESM, groups native rebuild under build.nativeModules (npmRebuild / nodeGypRebuild / rebuildMode), nests ASAR under build.asar (asar: true removed; use asar: { unpack: ['**/*.node'] }), and ships an automated `electron-builder migrate-schema`.
- quote: "v27 moves the entire electron-builder ecosystem to native ES modules, raises the minimum runtime to Node.js 22.12.0" / "Native-module options grouped under `nativeModules`"
- url: https://www.electron.build/docs/migration/v27-breaking-changes
- source_type: primary
- published: unknown (docs copyright 2026)
- confidence: high

### [12] electron-updater (with electron-builder) supports Linux, differential updates, staged rollouts, and providers GitHub Releases / S3 / Cloudflare R2 / generic HTTPS; v27 hardens updates (disableWebInstaller defaults true; autoInstallOnAppQuit replaced by autoInstallEvent with "onNextLaunch" planned as v28 default) and macOS auto-update requires code signing.
- quote: "macOS application must be signed in order for auto updating to work." / "autoUpdater.autoInstallEvent = \"onNextLaunch\"" / "Linux is supported (not only macOS and Windows)."
- url: https://www.electron.build/docs/features/auto-update
- source_type: primary
- published: unknown (docs copyright 2026)
- confidence: high

### [13] Pinia is the official Vue 3 default state manager; current docs are v3.x (v2.x archived); Vue 2 support was dropped in 2025; Pinia offers TypeScript inference, DevTools timeline, HMR, plugins, and testing utilities; no mutations — only state/getters/actions.
- quote: "Now that Pinia has become the default state management solution, it is subject to the same RFC process as other core libraries" / "Vue 2 support has been dropped in 2025"
- url: https://pinia.vuejs.org/introduction.html
- source_type: primary
- published: unknown
- confidence: high

### [14] electron-builder v27 also drops implicit --publish, filters node_modules by cpu/os against the target arch every build, and fails fast on Windows ia32 / Linux armv7l for Electron >=44 (Electron 44 removed those builds; 32-bit only on electronVersion <=43.x until EOL Jan 2027).
- quote: "Electron 44 removed Windows ia32 and Linux armv7l support. Use electronVersion <= 43.x to keep building for ia32"
- url: https://www.electron.build/docs/migration/v27-breaking-changes
- source_type: primary
- published: unknown (docs copyright 2026)
- confidence: high
